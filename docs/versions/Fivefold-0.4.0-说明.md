# Fivefold 0.4.0-alpha：共享进度、按键提示与分工表

适用 Minecraft Java 26.3 / NeoForge 26.3.0.39-beta / Java 25。
协议版本8；所有客户端和服务器一起升级，不能混用0.3.x。

## 1. 共控成员共享原版成就/进度

- 启动共控时，将房间内所有成员已有的进度取并集，补给每个人，不用身体玩家的进度覆盖别人的既有成果。
- 按具体条件同步，不只同步已完成的成就。例如不同成员各完成一个探索条件，合并后每个人都拥有这两个条件。
- 共控期间，任意成员的原版进度条件新增或撤销，都同步到本房间所有成员；其他房间、未参与共控的人不受影响。
- 同步写入每个玩家自己的原版进度数据，随游戏正常存档保存；解散后保留。解散之后各自新增的进度不再互相同步，下次开始共控重新合并。
- 同步副本不重复发放经验、物品、配方奖励或执行奖励函数，也不重复发送聊天成就公告。正常触发者的原版奖励流程仍照常执行。初始合并不补发历史奖励。
- 成员可使用本机绑定的“进度”键（默认L）打开原版进度界面查看。身体本人打开个人界面时，身体移动仍按原来的菜单规则停止。
- 范围为Minecraft原版进度系统，以及使用同一系统的数据包/模组进度；独立任务书、任务模组或平台成就不在此同步范围内。配方书解锁列表不是本次同步目标。

## 2. 屏幕显示自己的操作按键

- 共控期间左上角常驻“我的操作”，按移动、鼠标、辅助三组显示。
- 显示本机实际绑定的键名，例如修改前进键之后，提示随之变化。
- 鼠标左/右键、滚轮和Esc沿用该模组的固定输入规则。
- 分工改变后，清单随最新权限更新；权限空缺时继续显示分工不完整提示。
- 按F8查看所有成员的分工；F10仍是个人本地菜单。

此处每个人看到的是自己可操作的完整清单，避免多人所有按键同时堆在游戏画面上。全队负责人在F8表格中查看。

## 3. 重排三人分工界面

- 使用“操作为行、成员为列”的责任表，三人并排显示。
- 移动、鼠标、辅助三个标签页，每页五项操作，不再将15个窄按钮挤成五列。
- 自己的列显示“领取/已分配”按钮，其他成员的列直接显示勾选状态，不必悬停才能知道负责人。
- 操作无人负责时显示橙色行边；错误信息过长可悬停查看完整内容。
- 表格操作名使用短标签，本机改键一并显示；悬停操作名可看完整说明。
- 长玩家名可悬停查看；更多成员按列分页，默认定位到自己的页。
- 本次改善界面，不改变三人默认分工或权限组合规则。现有低延迟移动/视角链路保留。

## 安装

所有人退出游戏，停止专用服务器，移除旧Fivefold JAR，仅保留fivefold-0.4.0-alpha.jar。
所有客户端与服务器统一版本后重新创建房间，再启动共控。
启动时会实际合并现有进度，不只是临时显示一份共享界面。

## 建议复测

1. 三个人分别带有不同的已有进度，启动共控后按L比较，检查已完成和部分条件都已合并。
2. 由身体获得一个新进度，查看三个客户端是否同步。可用测试世界的原版进度命令检查部分条件授予和撤销。
3. 确认同步副本没有额外给予经验/掉落物；解散重进后确认进度保留。
4. F8逐页查看三人的分工，领取或取消自己的权限，检查屏幕清单更新；更改一个原版按键，检查键名提示。
5. 使用不同GUI缩放查看表格；继续复测转头、A/D、背包开关，确认体验没有回退。

## 验证状态

- 全部源码使用精确目标API，以Java 25编译通过。
- 68项纯Java逻辑、并发及布局几何测试通过。新增8项覆盖进度并集、重复同步、授予、撤销、非成员隔离、三列适配与页脚不重叠。
- 同步适配器参照目标版本PlayerAdvancements源码维护监听器、脏进度集合与可见性更新，未调用会再次发奖励的award方法。
- 新增Mixin的字段与方法名称、签名已对照精确目标源码；尚未进行本版游戏内Mixin加载、真实多人进度同步、存档重载或UI截图验收。纯逻辑测试不等于这些运行验收。
