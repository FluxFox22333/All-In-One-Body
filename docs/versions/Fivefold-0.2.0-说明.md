# Fivefold · 多人一体 0.2.0-alpha

适用：Minecraft Java 26.3 / NeoForge 26.3.0.39-beta / Java 25。
这是独立模组，不需要 Dual Drive。不要同时安装两个共控模组。

## 本版变化

从固定五人改为 **2～32人**；五人的默认分工保持不变。
人数是模组允许的房间人数范围，不代表已经完成32人性能或实际联机验收。实际人数还受服务器的 `max-players` 设置限制。

- 每个人可以选择多个移动、鼠标和辅助操作。
- 同一操作可以有多个负责人。设置中悬停可看到所有负责人。
- 开始前必须覆盖全部15项操作，且每个人至少有一项键盘操作和一项鼠标操作。
- 不允许把全部15项权限交给一个人。单人不能启动共控。
- 成员加入时自动按当前人数重新分配默认职责；因此请等人到齐后再自定义。
- 已开始共控的房间不接受新成员。调整人数时先解散，重新组队。成员掉线仍会解散整个房间并恢复原模式。

## 安装和开始

1. 所有客户端和专用服务器均安装同版本 NeoForge。
2. 删除旧 `fivefold-0.1.0-alpha.jar`，放入本版 `fivefold-0.2.0-alpha.jar`，不要同时保留两版。
   局域网房主客户端兼任服务器，所有加入者也需要安装本版。
3. 进入同一世界，按 F8，或打开“选项 → 多人一体”。NeoForge模组列表中也有配置入口。
4. 准备作为身体的玩家创建房间，其他人输入六位房间号加入。
5. 人到齐后，房主可点击“按人数分配”；每人也可勾选或取消自己的权限。
6. 全部权限有人负责、每人均有键盘和鼠标操作后，房主点击“启动多人共控”。
7. F8修改权限；F10打开个人本地菜单。“退出并解散”会结束整个会话。

本版修改了网络协议，不能与0.1.0混用。服务器重启后重新组队。

## 按人数默认分配

以下A～E指原来的五组职责，不是固定玩家姓名：

| 职责组 | 移动 | 鼠标 | 其他 |
|---|---|---|---|
| A | W 前进 | 左键 | Q 丢弃 |
| B | S 后退 | 右键 | E 打开背包 |
| C | A 左移 | 鼠标滑动 | Ctrl 疾跑 |
| D | D 右移 | 滚轮上滚 | Shift 潜行 |
| E | 空格 跳跃 | 滚轮下滚 | Esc 关闭共享界面 |

| 人数 | 按加入顺序的默认职责 |
|---|---|
| 2人 | 第1人A＋B；第2人C＋D＋E |
| 3人 | 第1人A＋B；第2人C；第3人D＋E |
| 4人 | 第1人A＋B；第2人C；第3人D；第4人E |
| 5人 | A、B、C、D、E各一人 |
| 6～32人 | A、B、C、D、E循环分配，第6人与第1人共享A组，以此类推 |

三人及以上仍限制：视角不能与前进、后退、跳跃配在一起；潜行不能与前进、后退、视角配在一起；疾跑不能与前进、后退配在一起。你指定的“视角＋疾跑”组合保留。
**两人模式放宽这些组合限制**，否则原来的职责隔离无法由两个人覆盖。每人仍需键盘和鼠标权限，不能由一人包办所有操作。

## 多人同时输入如何合并

- 同一持续按键：只要任一负责人按住就保持；所有负责人松开才停止。
- 左右相反或前后相反：按原版移动输入规则抵消。
- 攻击、使用、丢弃、打开背包等按下事件：依据合并按键的“未按→按下”变化触发，另一人重复按住同键不会额外触发一次。需要所有人松开后再按才产生新按下事件。
- 多个视角负责人：世界里的视角增量叠加；共享界面的指针采用服务器最后收到的位置。建议只留一位视角负责人，以免争抢指针。
- 滚轮：各负责人提交的合法滚动分别生效。
- 成员输入约20次/秒续期；服务器超过10个游戏刻没有收到更新，释放该成员的持续输入。服务器20TPS时约半秒。
- 修改权限会清除持续输入和待处理点击；如果出现操作空缺或某人缺少键盘/鼠标权限，停止主动身体操作，直到分工完整。

本版仍为按键分工玩法，没有添加“所有人同时按住协作键”。它不保证每一个动作都需要所有参与者同时按键。

## 共享身体、背包和退出

房主是唯一参与生存的真实角色。物品、生命、饥饿、经验、效果和属性由该角色持有和结算。其他人进入旁观模式跟随，并显示共享快捷栏和状态摘要；各自原有背包不会合并或复制到身体。

共享槽位界面中，由视角负责人移动绿色指针，左右键负责人点击，潜行负责人提供Shift快捷移动。Q丢弃指向槽位或光标拿着的物品；Ctrl＋Q丢弃整组。E打开，Esc负责人关闭。

数字键直接选快捷栏、中键选物品、副手交换、自动跳跃和双击W疾跑被屏蔽。基础键盘操作跟随原版改键；鼠标按钮、滚轮方向、Esc、F8和F10为本版固定输入。

身体客户端打开本地菜单时停止执行身体合并输入；成员本地菜单可独立操作。真实身体死亡后约三秒请求自动复活，硬核模式不支持。

正常退出或掉线后恢复跟随者原游戏模式，留在身体附近。转换旁观模式前保存世界目录的 `fivefold-recovery.json`；异常终止后再次登录时尝试恢复原模式。

## 已知边界与验证状态

本版已完成Java编译和10项自动化测试，包括2～32人默认分配覆盖、容量限制、五人预设保持、共享输入去重、部分松键、超时及权限撤销。
本版没有完成真实多人联机或32人压力测试。0.1.0曾完成开发服务器进入世界、开发客户端加载的检查；不能把旧版启动检查当成本版新增逻辑的联机验证。

原有Alpha限制仍然存在：
- 共享容器支持基础槽位取放、分堆、Shift快捷移动和基本合成。
- 尚不支持拖拽分配、双击收集、配方书、附魔选项、铁砧改名、交易切换、书本/告示牌编辑及其他模组特殊按钮。
- 炉子等容器仅显示槽位，不显示专属进度条。特殊槽位坐标可能需要单独适配。
- 跟随者状态是摘要，不完整复制第一人称手部动画或所有屏幕效果。
- 跨维度、死亡复活、骑乘、不同GUI缩放、第三方模组兼容性仍需实测。
- 这是合作控制模组，不是针对恶意修改客户端的反作弊插件。

## 首次测试建议

分别用2人、3人、5人、6人创建测试房间，检查默认分配和启动条件。6人时让两名A组玩家分别按住W，先松开其中一人，身体应继续前进；两人都松开才停止。共享左键应只有合并按下边沿触发一次。再检查鼠标、容器、权限改动和掉线恢复。

## 源码构建

安装JDK25：Windows执行 `gradlew.bat clean build`；macOS/Linux执行 `./gradlew clean build`。
输出 `build/libs/fivefold-0.2.0-alpha.jar`。首次构建需要联网下载官方依赖。
