# Fivefold 0.5.1-alpha：共享手部修复尝试与精简悬浮窗

Minecraft Java 26.3 / NeoForge 26.3.0.39-beta / Java 25，协议仍为 10。

## 手部修复尝试

针对 0.5.0 中操作者仍看不到手的反馈，改为在原版手部实际绘制入口准备共享身体状态，替换观看者自身的旁观者手部数据，并在同一渲染调用内放行旁观模式限制。移除了此前位于世界状态提取阶段的手部挂接。

主副手物品、惯用手、使用中的手、使用时间及望远镜状态继续来自服务器快照；弓弩决定显示哪只手时也统一使用该快照，避免与远端实体状态不一致。仅跟随共享身体、第一人称且身体存活、未睡眠时生效；个人背包仍保留。

这次是根据代码路径进行的修复尝试，尚未在实际多人游戏中确认反馈问题已经消失。隐身效果、望远镜使用时及 F1 隐藏 HUD 时仍遵循原版显隐规则。

## 悬浮窗

- 默认精简显示，左上角最多三行：房间状态、任务键/时间/响应人数与公共积分、当前目标玩家。每行背景按文字长度绘制，透明度降低。
- F7 在精简、详细、隐藏之间循环。隐藏后仍可按 F7 恢复。
- F9 在游戏内从精简或隐藏状态展开详细面板，再按可翻页查看全队按键；共享容器界面继续使用原有按键列表翻页。
- 详细分工面板缩窄，全队按键列表最大高度 80 GUI 像素，多人列表分页，减少长列表遮挡。
- F1 隐藏原版 HUD 时也隐藏这些悬浮内容。F8 分工、F10 菜单不变。
- 显示模式为当前客户端进程内的选择，重启后恢复精简模式；不会改变控制权限或任务计分。

## 任务调度调整

未提前完成的任务仍按每轮 15 秒运行。全员在有效的 3 秒响应窗口内完成任务时，立即结算并发放下一项任务，无须等待原来的剩余时间；新任务从发放时重新获得完整的 15 秒。只有部分成员响应时继续等待本轮到期结算。

切换任务时立即广播新任务编号、目标玩家、任务键与倒计时，清除本轮响应及最佳人数。计分、玩家轮换和暂停规则继续保留。上一轮的输入包不能响应新任务；持续按住不能跨轮自动参与，需要松开后重新按下。

## 安装与复测

退出客户端并停止服务器，移除旧版 JAR，所有客户端和服务器统一安装 `fivefold-0.5.1-alpha.jar`。

1. 至少两人进入测试世界并启动共控。分别让视角负责人和非视角操作者检查第一人称空手、主手物品、副手物品；与共享身体本人对比。
2. 检查左右惯用手、快捷栏切换、挖掘挥手、进食、主副手弓弩和望远镜；切到第三人称再返回第一人称。
3. 解散房间、重新组队、死亡及复活后检查；普通旁观模式不应出现共享身体的手。
4. 检查不同 GUI 缩放下默认最多三行；F7 三次切换可恢复精简，隐藏时 F9 可打开详情，多人按键列表可以翻页。
5. 按 F1、打开背包、关闭背包，检查 HUD 隐藏和恢复。确认任务响应及计分照常进行。
6. 全员提前完成一轮，检查立即获得下一项任务及新的 15 秒倒计时；仅部分响应时仍等待原轮到期。持续按住上一轮任务键不应计入新轮，松开重按后可以参与。
