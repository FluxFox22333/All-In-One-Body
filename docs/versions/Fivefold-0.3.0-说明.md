# Fivefold · 多人一体 0.3.0-alpha

适用：Minecraft Java 26.3 / NeoForge 26.3.0.39-beta / Java 25。
这是独立模组，不需要 Dual Drive。不要同时安装两个共控模组。

## 0.3.0：观看平滑、共享指针和原版容器

- 视角负责人继续逐帧本地预测，不增加观看端的平滑等待。
- 所有没有鼠标滑动权限的成员，包括身体原主人，使用约50毫秒的逐帧角度过渡。角度跨越正负180度时走短路径；旧快照、重复快照不会重启动画。平滑只改变绘制摄像机，不改变服务器实际朝向。
- 背包指针负责人本地立即看到指针移动，最多约60批/秒单独上传。其他人使用50毫秒指针缓冲，并合并短时间内成批到达的更新，减少跳格。
- 点击、右键分堆和Q丢弃按点击者最后一帧看到的共享指针位置结算。服务器用指针历史校验位置；切换容器后拒绝旧容器请求。鼠标滑动和左右键的职责仍然分离。
- 打开、关闭、取放、丢弃后立即广播状态；打开容器时按服务器游戏刻更新槽位和进度数据，正常20TPS时约20次/秒。指针更新不再夹带全背包物品。
- 持续按键变化和攻击/使用按下事件立即发送给身体客户端，减少等待下一次定时转发的时间；定时续期和断线释放机制保留。
- 原版背包槽位、物品提示、拿起的物品、装备空槽提示和身体模型通过原版容器渲染器显示。创造模式共控时也使用生存式背包，不开放创造物品目录。
- 常用容器使用原版界面：普通/大箱子、漏斗、潜影盒、发射器/投掷器、工作台、熔炉、高炉、烟熏炉、酿造台、砂轮、锻造台、制图台。同步原版菜单数据，包含适用的燃烧、加工和酿造进度。
- 界面使用独立的客户端显示背包，不覆盖观看者自己的物品。个人菜单、选项等仍使用原版；分工设置是模组专用界面。

50毫秒是渲染平滑参数，不是实测总延迟。其他成员仍要等待网络和服务器处理；身体移动位置仍使用原版同步，没有加入位置预测。客户端低帧率、服务器低TPS和网络抖动不会被本版消除。没有在你的实际联机环境中测得改善幅度。

## 人数与分工

从固定五人改为 **2～32人**；五人的默认分工保持不变。
人数是模组允许的房间人数范围，不代表已经完成32人性能或实际联机验收。实际人数还受服务器的 `max-players` 设置限制。

- 每个人可以选择多个移动、鼠标和辅助操作。
- 同一操作可以有多个负责人。设置中悬停可看到所有负责人。
- 开始前必须覆盖全部15项操作，且每个人至少有一项键盘操作和一项鼠标操作。
- 不允许把全部15项权限交给一个人。单人不能启动共控。
- 成员加入时自动按当前人数重新分配默认职责；因此请等人到齐后再自定义。
- 已开始共控的房间不接受新成员。调整人数时先解散，重新组队。成员掉线仍会解散整个房间并恢复原模式。

## 安装和开始

1. 所有客户端和专用服务器均安装同版本 NeoForge。
2. 删除所有旧版Fivefold JAR，放入本版 `fivefold-0.3.0-alpha.jar`，不要同时保留两版。
   局域网房主客户端兼任服务器，所有加入者也需要安装本版。
3. 进入同一世界，按 F8，或打开“选项 → 多人一体”。NeoForge模组列表中也有配置入口。
4. 准备作为身体的玩家创建房间，其他人输入六位房间号加入。
5. 人到齐后，房主可点击“按人数分配”；每人也可勾选或取消自己的权限。
6. 全部权限有人负责、每人均有键盘和鼠标操作后，房主点击“启动多人共控”。
7. F8修改权限；F10打开个人本地菜单。“退出并解散”会结束整个会话。

本版修改了网络协议，不能与任何旧版混用。服务器重启后重新组队。

## 按人数默认分配

以下A～E指原来的五组职责，不是固定玩家姓名：

| 职责组 | 移动 | 鼠标 | 其他 |
|---|---|---|---|
| A | W 前进 | 左键 | Q 丢弃 |
| B | S 后退 | 右键 | E 打开背包 |
| C | A 左移 | 鼠标滑动 | Ctrl 疾跑 |
| D | D 右移 | 滚轮上滚 | Shift 潜行 |
| E | 空格 跳跃 | 滚轮下滚 | Esc 关闭共享界面 |

| 人数 | 按加入顺序的默认职责 |
|---|---|
| 2人 | 第1人A＋B；第2人C＋D＋E |
| 3人 | 第1人A＋B；第2人C；第3人D＋E |
| 4人 | 第1人A＋B；第2人C；第3人D；第4人E |
| 5人 | A、B、C、D、E各一人 |
| 6～32人 | A、B、C、D、E循环分配，第6人与第1人共享A组，以此类推 |

三人及以上仍限制：视角不能与前进、后退、跳跃配在一起；潜行不能与前进、后退、视角配在一起；疾跑不能与前进、后退配在一起。你指定的“视角＋疾跑”组合保留。
**两人模式放宽这些组合限制**，否则原来的职责隔离无法由两个人覆盖。每人仍需键盘和鼠标权限，不能由一人包办所有操作。

## 多人同时输入如何合并

- 同一持续按键：只要任一负责人按住就保持；所有负责人松开才停止。
- 左右相反或前后相反：按原版移动输入规则抵消。
- 攻击、使用、丢弃、打开背包等按下事件：依据合并按键的“未按→按下”变化触发，另一人重复按住同键不会额外触发一次。需要所有人松开后再按才产生新按下事件。
- 多个视角负责人：世界里的视角增量叠加；共享界面的指针采用服务器最后收到的位置。建议只留一位视角负责人，以免争抢指针。
- 滚轮：各负责人提交的合法滚动分别生效。
- 成员输入约20次/秒续期；服务器超过10个游戏刻没有收到更新，释放该成员的持续输入。服务器20TPS时约半秒。
- 修改权限会清除持续输入和待处理点击；如果出现操作空缺或某人缺少键盘/鼠标权限，停止主动身体操作，直到分工完整。

本版仍为按键分工玩法，没有添加“所有人同时按住协作键”。它不保证每一个动作都需要所有参与者同时按键。

## 共享身体、背包和退出

房主是唯一参与生存的真实角色。物品、生命、饥饿、经验、效果和属性由该角色持有和结算。其他人进入旁观模式跟随，并显示共享快捷栏和状态摘要；各自原有背包不会合并或复制到身体。

共享界面中，以绿色指针为准，由视角负责人移动指针，左右键负责人点击，潜行负责人提供Shift快捷移动。Q丢弃指向槽位或光标拿着的物品；Ctrl＋Q丢弃整组。E打开，Esc负责人关闭。

数字键直接选快捷栏、中键选物品、副手交换、自动跳跃和双击W疾跑被屏蔽。基础键盘操作跟随原版改键；鼠标按钮、滚轮方向、Esc、F8和F10为本版固定输入。

身体客户端打开本地菜单时停止执行身体合并输入；成员本地菜单可独立操作。真实身体死亡后约三秒请求自动复活，硬核模式不支持。

正常退出或掉线后恢复跟随者原游戏模式，留在身体附近。转换旁观模式前保存世界目录的 `fivefold-recovery.json`；异常终止后再次登录时尝试恢复原模式。

## 已知边界与验证状态

本版使用精确目标版本的API完成Java编译，30项自动化测试通过：权限/合并按键10项，视角预测10项，观看角度与共享指针10项。包含20Hz更新/60Hz绘制模拟、角度接缝、停止/重置、突发指针包、点击位置还原和旧引用拒绝。

这些是算法测试，不是多人游戏或帧率测试。本版尚未完成真实多人联机、GUI画面验收或32人压力测试。以前版本的启动检查不能作为本版UI验收依据。

仍有以下Alpha限制：
- 原版容器已接入基础槽位取放、分堆、Shift快捷移动和基本合成；尚未接入拖拽分配、双击收集、配方书自动填充、收纳袋内部滚动选择。
- 配方书按钮暂时禁用，避免按各玩家自己的配方/背包状态操作共享身体。背包的配方书按钮不显示。
- 附魔台、村民交易、铁砧、织布机、切石机、信标、讲台、马背包及未知模组容器仍使用兼容槽位界面，特殊按钮、交易切换、改名/文字输入尚未接入。书本和告示牌编辑不属于本版支持的共享操作。
- 部分容器自定义名称暂用通用原版标题；原版UI不代表所有专用按钮都已实现。安全接入列表以外不强制套用原版界面。
- 跟随者状态是摘要，不完整复制第一人称手部动画或所有屏幕效果。
- 跨维度、死亡复活、骑乘、不同GUI缩放、资源包和第三方模组兼容性仍需实测。
- 这是合作控制模组，不是针对恶意修改客户端的反作弊插件。

## 升级后测试

所有人及服务器替换为同一个0.3.0版本，重新创建房间。先只留一名视角负责人：慢速转圈、快速左右转头、停下和抬头到顶，分别观察操作者、身体原主人及其他成员。重点检查观看顿挫是否减轻，操作者是否仍即时响应。

打开背包移动绿色指针，让另一人按左键/右键，分别试普通取放、右键分堆、Shift快捷移动、Q/整组丢弃、2×2合成。然后测试大小箱子、工作台和正在加工的炉子，检查原版布局、进度条和所有人的物品结果。使用不同GUI缩放重复测试；连续切换容器时，旧界面输入不应点到新容器。

多人分工、F8/F10、权限修改、离开/掉线恢复仍需一并检查。人数范围仍为2～32人。

## 源码构建

安装JDK25：Windows执行 `gradlew.bat clean build`；macOS/Linux执行 `./gradlew clean build`。
输出 `build/libs/fivefold-0.3.0-alpha.jar`。首次构建需要联网下载官方依赖。
