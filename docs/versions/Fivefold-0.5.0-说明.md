# Fivefold 0.5.0-alpha：交易与共享显示修复、协作奖惩任务

Minecraft Java 26.3 / NeoForge 26.3.0.39-beta / Java 25。
协议版本10。所有客户端与服务器必须统一升级，不能与旧版混用。

## 安装

退出所有客户端并停止服务器，移除旧Fivefold JAR，仅保留fivefold-0.5.0-alpha.jar。
重新启动、创建房间、分配权限并启动共控。F8查看分工，F9翻页查看全队实时按键，F10打开个人菜单，默认L查看进度。
原有共享成就、权限分工和即时移动/视角通道保留。

## 本次显示与同步修复

### 村民交易

0.4.1没有将村民交易加入原版界面代理，也没有传送MerchantOffers报价，因此只能看到通用槽位，缺少价格单。
本版使用原版MerchantScreen，同步完整报价、原价/折扣、库存状态、商人等级与经验、当前选择及列表滚动位置。
视角负责人移动共享光标，左键负责人选择报价和取出交易结果；滚轮负责人滚动报价列表，也可由左键负责人点击滚动条定位。实际交易仍由服务器上的共享身体完成。
翻页后，旧页面的点击请求会被拒绝，避免因页面更新延迟选错报价。任意拖拽滚动条未新增，滚轮与点击定位可用。

### 丢弃后身体玩家仍看到物品图标

原版ServerPlayer.drop会把所选槽位标记为“远端已知”，因为原版默认发起丢弃的客户端已经预测更新。
远程操作者触发丢弃时，身体客户端并未执行该预测，所以可能保留旧图标。
本版在丢弃后主动发送原版库存槽位更新，并立即发布共享状态；容器内丢弃也补齐广播更新。

### 主手、副手与使用状态

不再仅依赖旁观跟随时的原版装备复制。每份共享状态显式携带身体的主副手物品、当前快捷栏槽位、惯用手、使用中的手、使用剩余时间和望远镜状态。
所有跟随者都应用这些数据，与是否拥有视角权限无关。第一人称模型与物品状态使用共享身体快照；不覆盖观看者自己的个人背包。
仍使用原版第一人称渲染，并为共享手部状态放行旁观模式的手部隐藏限制。

### 原版物品栏与呼吸条

移除跟随者底部自绘的九格物品栏与文字生命条，改调用原版HUD绘制快捷栏、副手格、生命、护甲、饥饿、呼吸条，并绘制原版经验条和等级。
空气值、饥饿和经验等来自共享身体；跟随者原版旁观工具栏不再遮替这些显示。共享效果图标也显示身体的效果。
身体本人继续使用正常原版HUD。背包面板沿用原版InventoryScreen纹理和槽位绘制，面板外继续可见世界。

## 协作奖惩任务

### 发布与响应

- 每15秒一个任务，单个任务最多15秒；没有并行任务。计时使用服务器游戏时间，正常20 TPS下为上述秒数。
- 具有可用任务操作的成员随机排序，轮流被选中，全部选过后再打乱；从被选中者负责的可用操作中随机选一个。
- 任务池：前进、后退、左移、右移、跳跃、攻击/挖掘、使用、疾跑、潜行。
- 排除物品栏相关操作：打开背包、关闭共享界面、丢弃、上下滚轮。鼠标移动也不参与，避免无意移动被当作按键响应。
- 参与者按自己的绑定键即可；没有该操作控制权限的人，按键只参与任务，不能借此操作身体。
- **不需要按住，也不要求同时按下。每次按下检查最近3秒内响应过的不同玩家。**
- 只要未满员，窗口持续滑动。响应超过3秒即失效，需要松开再按下重新参与；每人最多计一次。
- 被选中者必须包含在当前窗口内，该窗口才算有效配合；保存整轮最高有效响应人数。
- 全员成功立即结算，等待下一固定轮次；未满员在任务结束时结算，每轮只结算一次。
- 持续按住、按键重复事件、重复网络包不会反复计入，也不能跨任务自动响应。

### 五人局积分

| 最高有效响应人数 | 公共奖励积分 | 被选中者惩罚积分 |
| --- | --- | --- |
| 0～1人 | 0 | +1 |
| 2～4人 | +0.5 | 不变 |
| 5人 | +1 | −1，最低0 |

其他人数采用同一比例：低于25%受罚；达到25%但未满员得0.5分；满员得1分并减罚。
例如四人局一人响应刚好为25%，属于半分档，且该人必须是被选中者。

### 效果触发

| 项目 | 正面奖励 | 负面惩罚 |
| --- | --- | --- |
| 积分归属 | 当前房间公共积分池 | 每名成员独立 |
| 门槛 | 4分 | 4分 |
| 施加对象 | 共享身体 | 共享身体 |
| 时长/等级 | 60秒、I级 | 10秒、I级 |
| 触发后积分 | 清零，溢出不保留 | 扣2分，最低0 |

只从原版注册的对应正面/负面类别中随机选择，中性与第三方效果不参与。
两个效果池统一排除：**瞬间治疗、瞬间伤害、黑暗、失明、挖掘疲劳**。
重复获得不会叠加等级；使用原版效果合并规则补充时间。如果身体已有更强或更长的药水效果，不强行降级或缩短该效果。
惩罚只有轮到本人并全员成功时才减1分；达到门槛后的扣2分单独执行。
积分属于当前房间，解散、断线导致房间解散或服务器重启后重置，不持久保存为个人档案。

### 界面与暂停

- HUD显示任务玩家、自己的任务键、倒计时、当前响应人数/名单、最佳人数与公共积分。
- 提前全员成功后，任务键显示红色与✓，避免重复尝试；到期半分结算后进入下一任务。
- 个人只收到自己的惩罚积分，以及最高分玩家的姓名和数值；并列最高者一并提供。长名单会按HUD可用宽度截断。
- 共享背包/容器打开、身体死亡或权限分工不完整时暂停任务时钟，并清除当前3秒窗口，保留本轮已取得的最佳人数。
- 相同成员之间修改分工不会清除当前任务或最佳成绩，新的分工用于后续任务。
- 没有可用任务键的成员不会被选为任务目标，但仍可响应其他人的任务。

## 验证结果与实际限制

- 精确目标Minecraft/NeoForge API下，Java25完整编译通过。
- 99项JUnit逻辑、并发和布局测试全部通过，较0.4.1新增23项。
- 新测试覆盖滑动窗口、3秒边界、松开重按、目标本人缺席、部分成功记录、多人比例、轮换公平性、积分清零与惩罚扣分、暂停、旧任务包、改分工不擦除成绩，以及原版交易行与滚动条坐标。
- 18项目标字节码检查通过，核对HUD、MerchantScreen、手部提取/渲染和状态重置的挂接位置。
- **没有实际启动本版游戏，没有多人联机、运行时Mixin变换或画面截图验收。编译与纯逻辑测试不能证明交易、手部和HUD已在真实环境完全修复。**
- 远端换物品时的手部升降动画仍未完整复制；地图缺少观看者端地图数据或第三方自定义渲染时可能有差异。
- 本版专门适配原版村民交易。其他第三方特殊容器仍可能使用兼容槽位界面。

## 建议复测顺序

1. 三至五人共控，打开村民交易，确认每个客户端均看到价格、折扣、缺货；超过七条报价时滚动、选择、买卖并检查物品扣除。
2. 由远程丢弃负责人按Q及疾跑键+Q，身体本人观察所选槽位数量和图标，打开背包确认库存一致；再测容器内丢弃。
3. 让不负责视角的玩家看空手、主手持物、副手持物、进食、弓弩和切换槽位；第一/第三人称切换后检查不残留错误手部。
4. 身体下水并持续消耗空气，对比所有客户端的呼吸条；出水后检查恢复，检查快捷栏、副手格和原版生命/饥饿显示。
5. 五人分别测试同一窗口仅1人、2人、5人响应，以及先4人、过期后重新凑齐5人。确认轻点即可，无须持续按住。
6. 累计公共4分，检查正面效果60秒并清零；个人惩罚达到4，检查共享身体负面效果10秒、该成员剩2分。让该成员下一次全员成功，检查只减本人1分。
7. 打开共享背包暂停任务后关闭，检查不误罚；长按跨轮不应得分。更改绑定键，检查任务按操作匹配。
8. 检查不同GUI缩放及原有A/D、视角、共享进度和F8三人分工，确认没有明显回退。
